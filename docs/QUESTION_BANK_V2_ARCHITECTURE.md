# 题库 v2 架构与维护规则

这份文件记录 Codex 重构题库 v2 时形成的架构边界。它们是发布约束，不是可随意调整的样式偏好。

## v2 为什么存在

v2 的核心目的不是“换一个页面样式”，而是清除重复 runtime、重复事件监听、重复控制器和相互覆盖的页面状态，避免 408 真题、Relax1000、整体图谱和组卷同时抢占同一页面生命周期。

### 1. 同一时间只启动当前选择的题库实现

`/zhenti/` 是统一题库外壳，但只能启动当前选中的一套实现：

- 选择「408 真题」时，只启动真题 runtime；
- 选择「Relax1000」时，只启动 Relax runtime；
- 禁止“真题和 Relax 都启动，再靠 CSS 隐藏其中一个”。

题库来源切换时允许整页重新初始化。这个 reload 是隔离边界：它确保旧 runtime 被销毁后再启动新 runtime，不应为了“看起来无刷新”而让两套题库控制器同时存在。

### 2. 题库、图谱、组卷必须分离

- `/zhenti/` 只负责题库；
- `/graph/` 只负责整体图谱；
- `/relax/` 只负责组卷；
- 三者可以共享数据格式和学习状态，但不能共享页面级控制器、快捷键生命周期或重复挂载 UI。

修改其中一项时，不允许顺手把另一项 runtime 引入当前页面。

### 3. 一个页面只能存在一份 Relax core

`relax1000-wall.js`、`relax1000-cards.js`、`relax1000-reset.js` 必须引用完全相同的 `relax1000-core.js?v=...` URL。

ES Module 会把不同 query URL 视为不同模块。如果 wall 引用 `core.js?v=A`、cards/reset 引用 `core.js?v=B`，浏览器就会加载两份 core；两份 core 会各自持有缓存，并重复安装 document 级监听器。这正是 v2 要消灭的问题。

**禁止只给某一个 Relax 子模块单独升级 core 版本。**需要升级时，wall/cards/reset 必须作为一组一起升级。

### 4. “点击题号 -> 打开题目”是关键交互契约

可见题号按钮渲染后，应直接绑定到当前题目 reader/open 函数。真题和 Relax 都应遵守这个行为：

`题号按钮 -> 定位当前题 -> 构建题目阅读层 -> 显示阅读层`

不要仅为了减少几百个轻量 click listener，就把这个最关键的热路径交给无关的页面级事件代理。

题目阅读层必须**先完成 DOM 内容构建，再显示 fixed/modal 层**。禁止先把空的全屏 modal 显示出来，再向里面写大量 DOM；在 iPad Safari 上这会放大样式重算和重排成本。

### 5. 单题变化只能局部更新

性能优化应放在“状态更新”而不是“打开路径”上：

- 提交答案，只更新当前题、当前题号状态和统计；
- 熟练/模糊/不会，只更新当前题号状态；
- 收藏，只更新当前题号和收藏状态；
- 图谱只更新当前格子；
- 速刷卡片打开时，隐藏的题库墙不得在后台反复重建；
- 禁止一次单题操作重建整科几百个题号或整张 Relax 图谱。

### 6. 学习数据与 UI 重构永远分离

不得因为 UI、缓存、性能或架构调整而清空或重写：

- 答题记录；
- 错题记录；
- 熟练/模糊/不会；
- 收藏；
- 笔记；
- SRS/速刷调度数据。

已有题目 ID 和 localStorage key 应保持稳定。

## iPad / Safari 是必测目标

Relax 题库不是只做桌面端验证。涉及题号、弹层、图谱或快捷答题的改动，发布前至少检查：

1. 打开 Relax1000；
2. 分别切换 DS / CO / OS / CN；
3. 切换章节；
4. 连续点击多个题号，题目阅读层应立即出现，背景页面不能冻结；
5. 测试关闭、上一题、下一题；
6. 测试 A-D 选择、提交、查看解析；
7. 测试收藏、熟练、模糊、不会；
8. 进入速刷卡片连续答题，再返回题库墙；
9. 回到 408 真题，确认真题 reader 完全不受影响。

只通过 `node --check` 不等于交互通过。

## 发布前检查

每次题库改动都要确认：

- v2 的“仅启动选中题库”仍然成立；
- bank / graph / paper builder 生命周期仍然分离；
- wall/cards/reset 的 core URL 完全一致；
- 没有重新引入重复 runtime；
- 没有把题号直接打开契约改成高风险全局代理；
- 单题操作不会重建整墙/整图；
- 缓存版本成组升级，不能一半新一半旧；
- GitHub Pages architecture audit 和 JavaScript syntax check 全部通过；
- 最终检查 Pages 实际 artifact，而不是只检查仓库源码。

## 2026-08-28 Relax 回归事故

后续一次 Relax 性能补丁违背了 v2 的两个边界：

1. `relax1000-wall.js` 使用了新的 core query，而 cards/reset 仍使用旧 query，重新产生了两份 Relax core module；
2. 稳定的“每个题号直接绑定打开题目”被替换成 wall 级事件代理，同时 open 流程变成先显示空 modal 再填充内容。

在 iPad 上表现为：点击 Relax 题号无法正常显示题目，并伴随严重卡顿/页面近似崩溃。

修复原则是恢复 v2 的交互边界，而不是继续在错误架构上叠更多补丁。
